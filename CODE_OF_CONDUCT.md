# SIEMBOX Code of Conduct

## Our Commitment

SIEMBOX exists to help people secure their homelabs. We want every contributor, user, and maintainer to feel welcome here, regardless of experience level, background, identity, or the size of their lab.

We commit to a respectful, harassment-free community for everyone.

## Expected Behavior

- Treat others with respect, even when you disagree.
- Assume good intent. Ask questions before drawing conclusions.
- Give feedback on code and ideas, never on people.
- Accept feedback without taking offense.
- Help newcomers. Everyone started with zero logs and zero rules.
- Credit others for their work, ideas, and detection rules.
- Keep discussions on topic and useful to the project.

## Unacceptable Behavior

- Harassment, insults, or personal attacks.
- Discriminatory language or jokes of any kind.
- Threats or intimidation.
- Publishing someone's private information without consent.
- Sexual language or imagery.
- Trolling, spam, or deliberate disruption.
- Pressuring maintainers or contributors for free support or fast responses.

## Security-Specific Rules

SIEMBOX handles sensitive data. These rules protect you and other users.

- Report vulnerabilities privately through the process in SECURITY.md. Never open a public issue for a security flaw.
- Scrub logs before you share them. Remove IP addresses, hostnames, usernames, tokens, and passwords from issues, pull requests, and discussions.
- Never post working exploits or attack tooling aimed at SIEMBOX users.
- Use SIEMBOX only on systems you own or have permission to monitor.

## Scope

This code applies in all project spaces, including GitHub issues, pull requests, discussions, and any chat or forum run by the project. The code also applies when you represent SIEMBOX in public spaces.

## Reporting

If you see or experience unacceptable behavior, contact the maintainers at cladkins@gmail.com. Include links, screenshots, and a short description of what happened.

Maintainers will review every report, respond within 7 days, and keep the reporter's identity private.

## Enforcement

Maintainers will take the action they judge fair for each violation.

1. Warning. A private message explaining the violation and the expected change.
2. Temporary ban. A set period with no interaction in project spaces.
3. Permanent ban. Removal from all project spaces.

Maintainers will skip steps for serious violations, such as threats or doxxing.

Maintainers who fail to follow or enforce this code in good faith face the same consequences.
